===============================================================================

                              Manual do TuxFrw-NFT
                              --------------------
                             
                                 (versão 5.0)

===============================================================================

TuxFrw-NFT consiste em um conjunto de shell scripts cujos conteúdos são
definições e regras de firewall para o subsistema Netfilter/nftables do Linux,
escritos de maneira modular para facilitar sua administração, auditoria e
manutenção em produção.

O sistema opera compilando dinamicamente um batch atômico de regras executado
diretamente via "/usr/sbin/nft -f". O TuxFrw-NFT opera nativamente em Dual-Stack
(IPv4 e IPv6 simultaneamente em todas as tabelas 'inet') e pode atuar tanto
em servidores de aplicação com Docker quanto em roteadores/gateways de borda
que interligam até três sub-redes corporativas:

- EXT ==> rede externa ou Internet. Interface voltada para acessos diretos.
          Existem filtros específicos neste ponto (inclusive pré-filtragem
          no estágio ingress via hook netdev) para mitigar ataques comuns de
          flags TCP inválidas, pacotes bogons/spoofados e varreduras.

- DMZ ==> rede desmilitarizada ou semi-protegida para servidores que hospedam
          serviços acessíveis publicamente (HTTP, HTTPS, DNS, SMTP, etc.).
          O TuxFrw-NFT protege a DMZ permitindo estritamente conexões autorizadas
          e isolando a DMZ do acesso irrestrito à rede interna corporativa.

- INT ==> rede interna ou corporativa. O TuxFrw-NFT controla todo o tráfego que
          sai da rede interna para a Internet e DMZ, registrando tentativas
          de tráfego indevido.


Recursos Arquiteturais do TuxFrw-NFT:
=====================================

1. Stateful Packet Inspection (ct state):
   Controle de estado de conexões (ct state related, established) tanto para
   IPv4 quanto IPv6, dispensando regras manuais de retorno de pacotes e
   rejeitando pacotes inválidos (ct state invalid).

2. Proteção Pré-Routing / Ingress com Netdev (tf_NETDEV.mod):
   Filtragem antes mesmo do subsistema de rede tradicional através de tabelas
   'netdev' nos hooks de ingress das placas físicas. Bloqueia anomalias de TCP
   flags (ex: pacotes sem flags, flags SYN/FIN simultâneas, Xmas scan) com custo
   mínimo de processamento de CPU.

3. Dual-Stack Unificado (inet filter):
   Ao contrário de soluções legadas que exigiam regras separadas para iptables e
   ip6tables, o TuxFrw-NFT utiliza a família 'inet', aplicando políticas e
   regras a pacotes IPv4 e IPv6 de forma unificada e concisa nos mesmos arquivos
   de módulo.

4. Network Address Translation (NAT) via nftables:
   No modo tradicional de gateway (DOCKER_SUPPORT="0"), suporta:
   - Masquerade / SNAT de saída em 'POSTROUTING' (tf_NAT-OUT.mod);
   - Port Forwarding / DNAT de entrada em 'PREROUTING' (tf_NAT-IN.mod).

5. Suporte Nativo e Isolado a Ambientes Docker (DOCKER_SUPPORT="1"):
   Permite rodar o TuxFrw-NFT em servidores que executam contêineres Docker sem
   destruir pontes virtuais (docker0, br-*), sem apagar as tabelas de NAT do
   Docker e permitindo controle refinado de portas de contêineres no FORWARD
   em prioridade superior (-5) antes das regras permissivas padrão do Docker.

Descrição dos Componentes:
==========================

- /usr/sbin/tuxfrw-nft:
  Programa executável de controle (CLI). Permite os comandos:
  start, stop, restart, status, panic, load <módulo>, natopen.

- /etc/tuxfrw-nft/tuxfrw.conf:
  Arquivo central de variáveis e flags. Define IPs de administração (SSH),
  interfaces físicas (EXT, INT, DMZ, VPNs), suporte a Docker (DOCKER_SUPPORT),
  portas de serviços permitidos e opções de carga do kernel.

- /etc/tuxfrw-nft/tf_BASE.mod:
  Núcleo de orquestração do firewall. Constrói a compilação do batch
  /etc/tuxfrw-nft/tuxfrw.nft e executa atomicamente o binário nft. Contém
  as rotinas:
  - clear_rules(): Limpeza segura (apaga apenas 'inet filter' se em modo Docker,
    ou 'flush ruleset' no modo roteador tradicional).
  - defines(): Declaração de sets de bogons IPv4 e IPv6.
  - create_rules(): Monta a hierarquia de tabelas, chains e módulos conforme
    o modo selecionado (Docker vs Tradicional).
  - run_nft(): Executa atomicamente o arquivo tuxfrw.nft gerado.

- /etc/tuxfrw-nft/tf_KERNEL.mod:
  Carrega módulos do kernel necessários (ex: nf_conntrack_ftp) e ajusta o
  parâmetro net.ipv4/ipv6 forwarding conforme a variável FORWARDING.

- /etc/tuxfrw-nft/rules/tf_INPUT.mod:
  Regras de proteção direcionadas ao host físico (hook input, policy drop).
  Trata tráfego de loopback (lo), conexões estabelecidas, mensagens essenciais
  de ICMPv4/ICMPv6 (Path MTU, Neighbor Discovery, Router Advertisement),
  DHCP (IPv4 67/68 e IPv6 546/547 link-local), liberação de SSH restrito por IP
  administrativo e serviços do host.

- /etc/tuxfrw-nft/rules/tf_OUTPUT.mod:
  Regras de tráfego originado no próprio host (hook output). Trata conexões
  estabelecidas, loopback, ICMPv4/ICMPv6 e saída de serviços locais.

- /etc/tuxfrw-nft/rules/tf_DOCKER.mod:
  Módulo exclusivo do modo Docker (DOCKER_SUPPORT="1"). Injetado na chain
  FORWARD da tabela 'inet filter' com prioridade -5 (superior à prioridade 0
  usada pelo Docker). Permite tráfego de saída dos contêineres para a Internet
  (interfaces docker0 e br-*), comunicação interna entre contêineres e
  oferece templates para filtragem seletiva de portas expostas (-p porta:porta).

- /etc/tuxfrw-nft/rules/tf_FORWARD.mod:
  Módulo de roteamento clássico entre interfaces (usado quando DOCKER_SUPPORT="0").
  Realiza os desvios (jump) para as chains direcionais (INT2EXT, EXT2INT,
  INT2DMZ, etc.).

- /etc/tuxfrw-nft/rules/tf_NETDEV.mod:
  Regras de descarte imediato na camada de interface física para anomalias TCP.

- /etc/tuxfrw-nft/rules/tf_NAT-IN.mod & tf_NAT-OUT.mod:
  Regras de DNAT (redirecionamento de portas) e SNAT (masquerade) para modo
  gateway clássico.

- /etc/systemd/system/tuxfrw-nft.service:
  Unidade systemd do serviço do firewall. Configurada com DefaultDependencies=no
  e Before=network-pre.target shutdown.target para proteção antecipada no boot.


Como Operar o TuxFrw-NFT:
=========================

1. Iniciar o Firewall:
   # tuxfrw-nft start
   (ou: systemctl start tuxfrw-nft)

2. Parar o Firewall:
   # tuxfrw-nft stop
   (ou: systemctl stop tuxfrw-nft)

3. Consultar o Estado e Regras em Memória:
   # tuxfrw-nft status
   Exibe as regras ativas compiladas no subsistema nftables.

4. Recarregar Apenas um Módulo Específico:
   O comando "load" recarrega atomicamente apenas a chain de um módulo
   específico sem reiniciar o firewall inteiro:
   # tuxfrw-nft load INPUT
   # tuxfrw-nft load OUTPUT
   # tuxfrw-nft load DOCKER
   # tuxfrw-nft load NETDEV
   # tuxfrw-nft load INT-EXT
   # tuxfrw-nft load NAT-IN

5. Modo Pânico (Isolamento Total):
   # tuxfrw-nft panic
   Interrompe o tráfego e fecha imediatamente conexões do host.


Modo de Compatibilidade com Docker (DOCKER_SUPPORT="1"):
========================================================

O Docker gerencia sua própria pilha de regras de NAT e pontes através do
Netfilter. Quando uma porta de contêiner é publicada (ex: -p 3000:3000), o Docker
cria uma regra de DNAT no PREROUTING e entrega o pacote para ser roteado na
chain FORWARD.

1. Por que usar DOCKER_SUPPORT="1"?
   - Sem o TuxFrw-NFT: O Docker publica a porta para 0.0.0.0/0 no FORWARD,
     deixando a aplicação do contêiner aberta para o mundo inteiro.
   - Com o TuxFrw original de IPTables: Ao iniciar, um "flush ruleset" destruía
     todas as pontes e tabelas do Docker, paralisando os contêineres.
   - Com o TuxFrw-NFT moderno: Limpa apenas a tabela 'inet filter' do TuxFrw,
     deixando o Docker 100% íntegro, blinda o host no INPUT e injeta o
     tf_DOCKER.mod no FORWARD em prioridade -5.

2. Como controlar acesso às portas dos contêineres:
   Edite o arquivo:
     /etc/tuxfrw-nft/rules/tf_DOCKER.mod

   Exemplo 1: Permitir acesso à porta web de um contêiner (ex: porta 3000)
   apenas a partir de um IP de gerência confiável:
     $NFT 'add rule inet filter FORWARD ip saddr 203.0.113.50 tcp dport 3000 counter accept'
     $NFT 'add rule inet filter FORWARD tcp dport 3000 counter drop'

   Exemplo 2: Permitir contêiner público (HTTP/HTTPS):
     $NFT 'add rule inet filter FORWARD tcp dport { 80, 443 } counter accept'

   Após editar o módulo, aplique a alteração instantaneamente sem derrubar
   nenhuma conexão existente:
     # tuxfrw-nft load DOCKER


Diagnóstico e Tratamento de Erros:
==================================

O TuxFrw-NFT compila as regras em /etc/tuxfrw-nft/tuxfrw.nft e executa
atomicamente com o utilitário "nft". Em caso de falha de sintaxe ou erro de
configuração:

1. Verifique os logs de erro gerados durante a execução:
   # cat /tmp/tf_error

2. Inspecione o arquivo batch gerado para identificar a linha com erro de sintaxe:
   # less /etc/tuxfrw-nft/tuxfrw.nft

3. Teste a validação de sintaxe diretamente com o interpretador nft:
   # /usr/sbin/nft -c -f /etc/tuxfrw-nft/tuxfrw.nft

4. Para acompanhar pacotes descartados pelo firewall:
   Verifique o log do sistema (journalctl ou rsyslog):
   # journalctl -k -f | grep "tuxfrw:"
   (Obs: certifique-se de que a linha de log do módulo desejado esteja descomentada).


Instalação e Inicialização no Boot:
===================================

Execute como root a partir do diretório do código-fonte:
  # ./install.sh

O instalador:
1. Copia o executável para /usr/sbin/tuxfrw-nft.
2. Copia as configurações e módulos para /etc/tuxfrw-nft/.
3. Instala a unidade de serviço /etc/systemd/system/tuxfrw-nft.service e recarrega
   o systemd (daemon-reload).

AVISO IMPORTANTE DE SEGURANÇA:
Por padrão, o instalador NÃO habilita o serviço no boot.
Primeiro, revise suas configurações (/etc/tuxfrw-nft/tuxfrw.conf) e módulos
de regras (/etc/tuxfrw-nft/rules/), inicie manualmente e certifique-se de que
o tráfego administrativo (SSH) e os acessos necessários funcionam perfeitamente.

Após validar o funcionamento, habilite o serviço para inicialização automática:
  # systemctl enable tuxfrw-nft
