===============================================================================

                             TuxFrw-NFT Manual
                             -----------------
                             
                               (version 5.0)

===============================================================================

TuxFrw-NFT consists of a collection of modular shell scripts containing
firewall definitions and rules for the Linux Netfilter/nftables subsystem,
written in a structured manner to facilitate management, auditing, and maintenance
in production environments.

The system dynamically compiles an atomic batch ruleset file executed directly
via "/usr/sbin/nft -f". TuxFrw-NFT natively operates in Dual-Stack (IPv4 and IPv6
simultaneously across all 'inet' tables) and can act either on application servers
running Docker containers or as edge routers/gateways interconnecting up to
three corporate network segments:

- EXT ==> external network or Internet. Public-facing interface directly exposed
          to the Internet. Specific filters are applied at this layer (including
          ingress pre-filtering via the netdev hook) to mitigate invalid TCP flag
          attacks, spoofed/bogon traffic, and port scanning.

- DMZ ==> demilitarized zone or semi-protected network for servers hosting
          public-facing services (HTTP, HTTPS, DNS, SMTP, etc.). TuxFrw-NFT
          strictly allows only explicitly authorized connections and isolates
          the DMZ from accessing internal corporate resources.

- INT ==> internal corporate network (LAN). TuxFrw-NFT controls all outbound
          traffic originating from the internal network destined to the Internet
          and DMZ, logging unauthorized connection attempts.


TuxFrw-NFT Architectural Features:
==================================

1. Stateful Packet Inspection (ct state):
   Full connection state tracking (ct state related, established) for both IPv4
   and IPv6, eliminating the need for manual return-traffic rules and dropping
   invalid packets (ct state invalid).

2. Pre-Routing / Ingress Filtering with Netdev (tf_NETDEV.mod):
   Low-overhead packet dropping at the physical network interface layer via
   nftables 'netdev' ingress hooks. Drops TCP flag anomalies (null packets,
   SYN/FIN scans, Xmas attacks) before reaching the kernel IP stack.

3. Unified Dual-Stack (inet filter):
   Unlike legacy firewalls requiring separate iptables and ip6tables scripts,
   TuxFrw-NFT uses the unified 'inet' family, enforcing policies and rules
   across IPv4 and IPv6 consistently within the same module files.

4. Network Address Translation (NAT) via nftables:
   In traditional gateway mode (DOCKER_SUPPORT="0"), supports:
   - Outbound Masquerade / SNAT in 'POSTROUTING' (tf_NAT-OUT.mod);
   - Inbound Port Forwarding / DNAT in 'PREROUTING' (tf_NAT-IN.mod).

5. Native Isolated Docker Integration (DOCKER_SUPPORT="1"):
   Runs seamlessly on servers hosting Docker containers without wiping virtual
   bridges (docker0, br-*), preserving Docker NAT tables and enforcing granular
   container port access control on the FORWARD hook with priority -5 (before
   Docker's default permissive rules at priority 0).

Component Overview:
===================

- /usr/sbin/tuxfrw-nft:
  Main CLI management script. Supports commands:
  start, stop, restart, status, panic, load <module>, natopen.

- /etc/tuxfrw-nft/tuxfrw.conf:
  Central configuration file. Defines administrative IPs (SSH), physical
  interfaces (EXT, INT, DMZ, VPNs), Docker support flag (DOCKER_SUPPORT),
  service ports, and kernel module options.

- /etc/tuxfrw-nft/tf_BASE.mod:
  Firewall engine orchestrator. Builds the atomic /etc/tuxfrw-nft/tuxfrw.nft
  batch file and executes nft. Contains key functions:
  - clear_rules(): Safe flushing (only removes 'inet filter' in Docker mode,
    or runs 'flush ruleset' in traditional router mode).
  - defines(): Declares bogon sets for IPv4 and IPv6.
  - create_rules(): Orchestrates tables, chains, and modules according to the
    active operational mode.
  - run_nft(): Atomically loads the generated ruleset into kernel memory.

- /etc/tuxfrw-nft/tf_KERNEL.mod:
  Loads required kernel modules (e.g. nf_conntrack_ftp) and controls kernel
  packet forwarding sysctl based on the FORWARDING parameter.

- /etc/tuxfrw-nft/rules/tf_INPUT.mod:
  Host protection rules (hook input, policy drop). Manages loopback traffic,
  established connections, essential ICMPv4/ICMPv6 (Path MTU, Neighbor
  Discovery, Router Advertisement), DHCP, and administrative SSH access.

- /etc/tuxfrw-nft/rules/tf_OUTPUT.mod:
  Local host outbound rules (hook output). Manages established states, loopback,
  ICMPv4/ICMPv6, and local service egress.

- /etc/tuxfrw-nft/rules/tf_DOCKER.mod:
  Dedicated Docker mode module (DOCKER_SUPPORT="1"). Attached to the FORWARD
  chain in 'inet filter' with priority -5 (evaluated BEFORE Docker's priority 0).
  Permits outbound container traffic (docker0 and br-*), intra-container traffic,
  and templates for granular container port access control.

- /etc/tuxfrw-nft/rules/tf_FORWARD.mod:
  Classic routing module (used when DOCKER_SUPPORT="0"). Handles jumps to
  directional chains (INT2EXT, EXT2INT, INT2DMZ, etc.).

- /etc/tuxfrw-nft/rules/tf_NETDEV.mod:
  Ingress filtering module for physical interfaces dropping malformed TCP flags.

- /etc/tuxfrw-nft/rules/tf_NAT-IN.mod & tf_NAT-OUT.mod:
  DNAT (port forwarding) and SNAT (masquerade) rules for gateway mode.

- /etc/systemd/system/tuxfrw-nft.service:
  Systemd unit service configured with DefaultDependencies=no and
  Before=network-pre.target shutdown.target for safe early boot protection.


Operating TuxFrw-NFT:
=====================

1. Start Firewall:
   # tuxfrw-nft start
   (or: systemctl start tuxfrw-nft)

2. Stop Firewall:
   # tuxfrw-nft stop
   (or: systemctl stop tuxfrw-nft)

3. Inspect Active Ruleset:
   # tuxfrw-nft status
   Displays current nftables rules active in the kernel.

4. Reload a Specific Module:
   The "load" command atomically flushes and reloads only a specific module
   chain without restarting the entire firewall:
   # tuxfrw-nft load INPUT
   # tuxfrw-nft load OUTPUT
   # tuxfrw-nft load DOCKER
   # tuxfrw-nft load NETDEV
   # tuxfrw-nft load INT-EXT
   # tuxfrw-nft load NAT-IN

5. Panic Mode (Total Isolation):
   # tuxfrw-nft panic
   Immediately cuts traffic and closes all host connections.


Docker Compatibility Mode (DOCKER_SUPPORT="1"):
================================================

Docker manages its own NAT and bridge rules in Netfilter. When a container port
is published (-p 3000:3000), Docker adds a DNAT rule in PREROUTING and forwards
the packet to the FORWARD chain.

1. Why use DOCKER_SUPPORT="1"?
   - Without TuxFrw-NFT: Docker opens the published port to 0.0.0.0/0 in FORWARD,
     leaving container applications globally exposed.
   - With legacy IPTables TuxFrw: "flush ruleset" destroyed Docker bridges and
     chains, breaking container networking completely.
   - With modern TuxFrw-NFT: Only removes TuxFrw's own 'inet filter' table,
     leaving Docker intact, hardens the host in INPUT, and inserts tf_DOCKER.mod
     in FORWARD with priority -5.

2. Restricting Container Port Access:
   Edit:
     /etc/tuxfrw-nft/rules/tf_DOCKER.mod

   Example 1: Allow container port 3000 ONLY from trusted management IP:
     $NFT 'add rule inet filter FORWARD ip saddr 203.0.113.50 tcp dport 3000 counter accept'
     $NFT 'add rule inet filter FORWARD tcp dport 3000 counter drop'

   Example 2: Allow public web container (HTTP/HTTPS):
     $NFT 'add rule inet filter FORWARD tcp dport { 80, 443 } counter accept'

   Apply changes instantly without restarting the firewall or disrupting connections:
     # tuxfrw-nft load DOCKER


Troubleshooting & Error Diagnosis:
==================================

TuxFrw-NFT compiles rules into /etc/tuxfrw-nft/tuxfrw.nft and executes
them atomically with "nft". In case of errors:

1. Check runtime error log:
   # cat /tmp/tf_error

2. Inspect the generated batch ruleset:
   # less /etc/tuxfrw-nft/tuxfrw.nft

3. Test syntax validation with the nft interpreter:
   # /usr/sbin/nft -c -f /etc/tuxfrw-nft/tuxfrw.nft

4. Monitor dropped packet logs:
   # journalctl -k -f | grep "tuxfrw:"
   (Ensure log rules in the desired module are uncommented).


Installation and Boot Initialization:
=====================================

Run as root from the source repository directory:
  # ./install.sh

The installer:
1. Copies executable to /usr/sbin/tuxfrw-nft.
2. Copies configuration and modules to /etc/tuxfrw-nft/.
3. Deploys systemd unit /etc/systemd/system/tuxfrw-nft.service and executes
   systemctl daemon-reload.

IMPORTANT SECURITY NOTICE:
The service is NOT enabled at boot by default.
First, review your settings (/etc/tuxfrw-nft/tuxfrw.conf) and rule modules
(/etc/tuxfrw-nft/rules/), start the firewall manually, and verify that
remote SSH access and required services function as expected.

After verifying rules, enable automatic startup at boot:
  # systemctl enable tuxfrw-nft
